# 維持開放多語；草稿標示＋後處理硬閘

學習端**不**以語種允許清單封鎖分析；策展只補高頻／硬句。未命中已驗證空耳時：

1. 對 LLM 產空耳加 **「AI 草稿／未經聽感核定」** 標示；且  
2. **必須**經過**後處理硬閘**（兒化／拉丁殘渣／非許可腳本等）：不合格則拒收或自動重試後再顯示，不得把未過閘輸出當成功結果。

**雙軌**：後處理硬閘（交付閘，決策不變）＋**持續 Prompt 迭代**（主連續改善槓桿；多數「後續處理」可先是新版 Prompt，而非只寫硬代碼過濾）。硬閘不被 Prompt 取代；Prompt 也不因有硬閘而停止迭代。

**Status**: accepted（已修正：後處理硬閘由「延後」改為**本階段範圍內**；補充雙軌說明不撤銷硬閘）  
**Decided in**: Station 1 Round 1 Q4=A；Round 2 曾選僅標示；Station 1 close **C2 覆核＝B＋D**  
**Tension**: 不採用語種允許清單；信任改由標示＋硬閘＋點狀金標組合承接，並以 Prompt 版本演進壓低源頭壞輸出。

## Considered Options

- **開放多語＋標示＋硬閘（選定，本階段）**。  
- **僅標示、硬閘延後**：曾短暫採納，**已撤銷**。  
- **允許清單／雙軌限語**：未採。  
- **只靠 Prompt、取消硬閘**：未採（與「雙軌」不同；雙軌＝閘＋Prompt 並行）。

## Consequences

- 殘餘風險**相對降低**（明顯殘渣／兒化較難直出）；聽感「不像原詞」但形式合法的空耳仍可能過閘——此類更仰賴 Prompt 與金標。  
- 硬閘失敗路徑需有重試上限與對使用者的清楚錯誤／再試 CTA，避免無限轉圈。  
- 與既有 schema 驗證互補：schema 管結構；硬閘管字元／禁則內容；Prompt 管生成質量。  
- Web 平行上線仍增加草稿曝光面，但曝光內容應已過閘。
