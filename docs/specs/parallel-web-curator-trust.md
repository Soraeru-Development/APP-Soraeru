# 平行切片：Web 學習端＋策展端＋分析信任閘

## Problem Statement

Prompt 產出「長得像空耳」已夠跑通流程，但聽感可信度不足：拉丁殘渣、兒化等會讓學習者覺得「這根本不像」。Prompt 迭代仍是主改善槓桿，但單靠一輪通用改寫不足以保證每次輸出過關，故需硬閘與金標並行。同時，沒有 App 的人無法使用現有 Android 學習體驗；內部也缺少把人工核定空耳穩定餵回產品的管道。

產品表面採 **App 為準（canonical）**、Web 為**一級學習通道**的路徑（類比 Duolingo：功能與體驗以 App 為主軸演進，但使用者仍可在瀏覽器登入走同一產品學習路徑，而非另開玩具站）。MVP1 Web 頁面仍維持薄子集（登入、輸入、結果、單字本），目標是產品路徑對齊，而非當下功能面與 App 逐一對等。

學習者需要：在瀏覽器也能登入、分析、存單字本，且看到的空耳若未經核定必須誠實標示，並盡量擋掉明顯違規字元。策展者需要：用允許清單進入獨立後台，維護高頻／硬句的已驗證空耳，讓命中查詢不必再賭 LLM 的空耳欄位。

## Solution

在既有 App 與共用 ASP.NET API 之上，平行交付兩條薄前端與一條加硬的分析管線：

1. **Web 學習端**（Blazor）：登入、手動輸入、分析結果、單字本；無相機／OCR；與 App 共用產品路徑與帳戶語意（App-first／parity 軌跡，見 Problem Statement）。  
2. **策展端**（獨立 Blazor 站）：Google 允許清單；對已驗證空耳做最小 CRUD。  
3. **分析管線**：先查已驗證空耳 → 命中則金標優先覆寫空耳欄位（不呼叫 LLM 產空耳），詞義／正式讀音仍可 LLM；未命中則 LLM 產空耳，並套用 **草稿標示** 與 **後處理硬閘**（不合格拒收／有限次自動重試）。語種維持開放，不以允許清單封鎖分析。**雙軌改善**：硬閘為交付閘；**持續 Prompt 迭代**仍是主提升槓桿（非「只靠後處理程式」）。

App、Web、策展共用同一後端；以授權區分學習者與策展者能力。

## User Stories

1. As a 學習者, I want 在瀏覽器 Google 或 Email 登入, so that 沒有 App 也能使用同一帳號資料與額度。  
2. As a 學習者, I want 在 Web 手動輸入外語單字並分析, so that 取得詞義、正式讀音與空耳候選。  
3. As a 學習者, I want Web 不要求相機或 OCR, so that 我仍能完成核心記憶流程。  
4. As a 學習者, I want 將選定空耳存成單字卡並在單字本查看／刪除, so that 之後能複習。  
5. As a 學習者, I want App 與 Web 共用額度語意, so that 換裝置不會變成兩套計數規則。  
6. As a 學習者, I want 當空耳來自 LLM 時看到「AI 草稿／未經聽感核定」標示, so that 我知道要自行判斷聽感。  
7. As a 學習者, I want 當空耳來自已驗證命中時看到可區分的「已核定／策展」狀態, so that 我更有信心採用。  
8. As a 學習者, I want 含兒化或拉丁殘渣等違規的 LLM 空耳不要被當成成功結果顯示, so that 明顯壞輸出被擋下。  
9. As a 學習者, I want 硬閘觸發自動重試有上限且失敗時有清楚錯誤, so that 我知道可以稍後再試而非空轉。  
10. As a 學習者, I want 查詢任何可偵測來源語都能嘗試分析, so that 產品「不只英美日」的承諾仍成立。  
11. As a 學習者 on App, I want 既有分析／單字本行為與新的標示與硬閘一致, so that 信任改善不只在 Web。  
12. As a 策展者, I want 用允許清單內的 Google 帳號登入獨立策展站, so that 一般學習者進不了維護面。  
13. As a 策展者, I want 新增已驗證空耳（語言、原詞、displayText、notationText、explanation）, so that 高頻／硬句可被命中覆寫。  
14. As a 策展者, I want 編輯與啟用／下架已驗證空耳, so that 錯條可修正或停用。  
15. As a 策展者, I want 列表／搜尋已驗證條目, so that 我能管理覆蓋庫。  
16. As a 學習者, I want 當我的查詢命中啟用中的已驗證空耳時直接拿到核定空耳欄位, so that 不依賴該次 LLM 的聽感運氣。  
17. As a 學習者, I want 即使空耳已驗證，詞義與正式讀音仍可取得, so that 單字卡資訊完整。  
18. As a 策展者, I want 非允許清單帳號無法呼叫策展寫入 API, so that 金標庫不被任意竄改。  
19. As a 產品維運者, I want App／Web／策展打同一後端, so that 覆寫與額度規則只有一份真相。  
20. As a 產品維運者, I want 社群投稿與審核佇列先不做, so that 本切片范围可控。  
21. As a 學習者, I want 分析結果頁能選一個空耳候選再儲存, so that 行為與 App MVP 心智模型一致。  
22. As a 學習者, I want 看到隱私／AI 內容相關聲明入口（可極簡）, so that 知情同意不被 Web 子集砍光。

## Implementation Decisions

### 架構邊界

- **單一 ASP.NET API** 服務三端（ADR-0006）。  
- **Web 學習端**、**策展端**各自為 Blazor 應用、分開部署（ADR-0002、0005）；Blazor 宿主（Server／WASM／Unified）本規格不鎖定。  
- Android App 既有客戶端繼續使用同一分析／帳號／單字本語意；必須吃到草稿標示與硬閘結果欄位。  
- 沿用既有 Clean Architecture 分層思維：領域規則（覆寫、硬閘、授權）不放在 UI。

### 已驗證空耳（資料／契約）

- 欄位下限：語言、原詞（正規化後作為查詢鍵）、`displayText`、`notationText`、`explanation`、啟用／下架。  
- 查詢鍵：語言＋正規化原詞；啟用中才可被分析命中。  
- CRUD 僅策展者授權；學習者唯讀經由分析結果間接獲得，不暴露完整管理列表給一般使用者。

### 分析管線（順序）

1. 驗證登入與額度（開發者／策展允許清單帳號之無限額度政策可與既有 developer 政策對齊）。  
2. 以語言＋正規化原詞查已驗證空耳。  
3. **命中**：空耳欄位取自已驗證條目，**跳過 LLM 產空耳**；詞義／正式讀音仍可走既有 LLM／其他來源；結果標記為已驗證空耳來源。  
4. **未命中**：呼叫 LLM 產空耳（及既有 schema 驗證／重試）；通過後進入**後處理硬閘**；再標記為 LLM 草稿。  
5. 硬閘失敗：有限次自動重試（與／或重新要 LLM）；耗盡則失敗回應，不回傳未過閘候選為成功。  
6. 回應需讓客戶端能區分：`verified` vs `llm_draft`，以及硬閘／schema 類錯誤碼。

### 後處理硬閘（本階段範圍內）

- 至少規則簇：不當兒化（如孤立或禁則「兒／爾」用法）、孤立拉丁字母／片段、非許可腳本滲入（相對空耳應為漢字為主之輸出）。  
- 作用對象：LLM 產空耳候選（逐候選或整包政策擇一，規格要求：**任一將顯示的候選都必須過閘**）。  
- 已驗證覆寫：預設信任策展內容；可選做同一套輕量掃描作為防衛，但策展匯入失敗不應默默改成 LLM。

### 策展授權

- Google 登入成功後，email ∈ 允許清單才可存取策展 UI 與管理 API。  
- 建議與既有 developer email 設定同源或共用；一般學習者 JWT 呼叫管理端點必須 403。

### Web 學習端頁面範圍

- 定位：App 為 canonical；Web 是一級學習者通道（Duolingo 式 App-first），本切片頁面為**對齊產品路徑的薄 MVP1**，非永久玩具子集。  
- 必做：登入（Google 與／或既有 Email 流程）、手動輸入、分析結果（含標示）、單字本列表／詳情（含儲存選定候選）。  
- 不做（本切片）：相機、相簿、裝置 OCR、完整設定商場化；額度顯示可嵌結果流或極簡帳戶區。後續 parity 可擴，但不推翻上述薄 MVP1 起點。

### 客戶端顯示

- LLM 路徑：顯著「AI 草稿／未經聽感核定」。  
- 已驗證路徑：顯著不同狀態（例如「聽感已核定」）。  
- 二者文案可調，但語義不可混用。

## Testing Decisions

- **好測試**：只測外部行為（給輸入／雙緒狀態 → 可觀察的分析結果、錯誤碼、是否呼叫 LLM、標示旗標、CRUD 授權），不測私有實作細節。  
- **優先 seams**（由高到低、宜少）：  
  1. 分析應用服務：命中已驗證 → 不產空耳 LLM；回傳 verified 旗標與空耳欄位。  
  2. 後處理硬閘純函式／埠：違規字串拒收、合規放行。  
  3. 未命中＋硬閘失敗耗盡 → 失敗、無成功候選。  
  4. 策展管理 API：允許清單可寫、一般使用者 403。  
  5. 已驗證 CRUD 後，學習者分析同鍵可命中。  
- **Prior art**：repo 目前幾乎無自動化測試專案；分析側已有 schema 驗證與失敗重試行為，新測試應與該契約並存，另增硬閘與覆寫案例。建議新建標準 .NET 測試專案覆蓋 Application 層行为。  
- Web／策展 UI：本切片以 API 合約測試為主；UI 可後補煙測。

## Out of Scope

- 社群投稿、審核佇列、開放貢獻者角色。  
- 語種允許清單封鎖分析。  
- Web OCR／相機。  
- iOS。  
- 完整 SRS／複習演算法。  
- 真實金流／訂閱扣款 UI。  
- 將已驗證空耳擴成強制含詞義／正式讀音的整包靜態（命中仍可 LLM 補這兩類）。  
- 鎖定 Blazor Server vs WASM。  
- 用 Prompt 迭代**完全取代**後處理硬閘或金標覆寫（二者與 Prompt 為**雙軌**：閘擋壞輸出，Prompt 持續拉高聽感；迭代 Prompt 是重要改善槓桿，但不撤銷硬閘決策）。
